# Scaffold carillon-core

Created the carillon-core repository as its own git repo under pimalaya/carillon, the shared async watch client both Carillon frontends will depend on. This is the first stone: the type surface and the module skeleton, with the watch entry point stubbed pending the protocol relocation.

Adopted Cairn from the start: the `cairn/` root with spec, changes, and log, the activation surface (AGENTS.md with CLAUDE.md) and the verify.sh Stop hook vendored from pimalaya/cairn. Seeded the spec with one capability, watch-client, holding current truth: an async client rather than a sans-io layer, a content-free self-addressed event, a resolved credential with no keyring or OAuth inside core, a transport class per source, and a one-session watch entry point with looping left to the frontend.

## What landed

Applied the Pimalaya guidelines from commit one. Every public item carries the `Carillon` domain prefix (naming-006, naming-007): `CarillonEvent` and `CarillonSource` in the event module, `CarillonBackend` with `CarillonImapBackend`, `CarillonCardDavBackend` and `CarillonTransportClass` in the backend module, `CarillonCredential` in the credential module, and `watch` with `CarillonWatchError` and `CarillonWatchResult` in the client module. Types live next to the code that owns them with no catch-all and no root re-exports (naming-004, naming-005). The lib.rs header is the crate architecture document (header-001). Every public item is documented and struct fields carry no blank lines between them (inline-002, inline-003). The manifest follows the library field order with the docs.rs metadata block (cargo-001, cargo-005), and the repository ships the standard skeleton (repo-001).

The event dropped the shipped backend's `uid`, CardDAV `resource`, and `ChangeKind`: a doorbell says only that something changed at an address, never what or how. The product is in beta, so the break was free to take now.

## Deferred

The watch entry point returns `CarillonWatchError::NotImplemented`. The next layer relocates the IMAP session and pump and the CardDAV poller out of carillon-server into core, behind per-protocol features that pull io-imap and io-webdav, and dispatches on the backend. No cargo features exist yet, since gating code that pulls no extra crate is banned (crate-003); the features arrive with those dependencies.

## Governing change

The cross-repo split is proposed in carillon-server under cairn/changes/carillon-core-split, still active. That change also renames the frontend and website repos and re-expresses webhook and SSE delivery as consumers around core. This log records only the core-side scaffold.
